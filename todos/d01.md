## 🔧 Implementation details

### Railway (manual — you do this)
1. 👤 Create Railway project → add **MySQL** plugin (1 click).
2. 👤 Copy the auto-generated `DATABASE_URL` into `server/.env`.
3. App runs on your laptop; only the DB is remote.

### `.env` (server/.env)
```
DATABASE_URL=mysql://...        # from Railway
JWT_SECRET=<long random string>
SUPER_ADMIN_EMAIL=hoa.tranbinh@gameloft.com
PORT=3000
NODE_ENV=development
# EMAIL_FROM / RESEND_API_KEY — deferred to MVP
```

### Folder structure
```
/server
  /config        slots.js, db.js
  /db            /migrations  (001..004 .sql), migrate.js, seed.js
  /middleware    auth.js, role.js, error.js
  /routes        index.js, auth.js, vehicles.js, bookings.js
  /controllers   authController.js, bookingController.js, ...
  /services      mailer.js   (console-log impl; Resend later)
  app.js
  package.json
```

### Migrations (run in order)
- `001_create_users.sql` — `user_id, email UNIQUE, name, department, role ENUM('employee','admin','super_admin') DEFAULT 'employee', is_active BOOL DEFAULT TRUE, created_at`
- `002_create_otp_codes.sql` — `id, email, code_hash, expires_at, attempts DEFAULT 0, used BOOL DEFAULT FALSE, created_at`
- `003_create_vehicles.sql` — `vehicle_id, license_plate, vehicle_name, capacity, driver_name, status ENUM('active','maintenance') DEFAULT 'active', notes, created_at`
- `004_create_bookings.sql` — booking fields + `status ENUM('pending','approved','rejected','completed','cancelled') DEFAULT 'pending'` + `UNIQUE (vehicle_id, booking_date, slot_start)`

### Seed data
- 3 vehicles (e.g. Innova 01/02, Vios 01).
- 3 users: `employee@...`, `admin@...`, and `SUPER_ADMIN_EMAIL` as `super_admin`. The super_admin row's email must match the env var.
