# Day 2 — Email OTP Authentication

> **Build the OTP flow first** (per design). OTP hashing = **SHA-256**. OTP code printed to **server console** in dev — no email needed.

---

## 🎯 Goal (achieve by end of day)

Full login loop works via curl/Postman: request OTP → read code from server console → verify → receive a JWT containing the user's role. Protected routes reject missing/invalid tokens and enforce roles.

**Runnable at end of day:**
```bash
# server running on :3000
curl -X POST localhost:3000/api/v1/auth/request-otp \
  -H 'Content-Type: application/json' -d '{"email":"admin@..."}'
# → OTP prints in server console

curl -X POST localhost:3000/api/v1/auth/verify-otp \
  -H 'Content-Type: application/json' -d '{"email":"admin@...","code":"123456"}'
# → { token, user }
```

## 🔧 Implementation details

### `POST /auth/request-otp`
1. Validate email format.
2. Lookup user `WHERE email = ? AND is_active = TRUE`.
3. **If not found/inactive → still return 200 with the generic message** (do not reveal existence). Skip code generation.
4. If found:
   - Generate 6-digit code (`crypto.randomInt(100000, 1000000)`).
   - `code_hash = sha256(code + email)` (salt with email to avoid cross-row reuse).
   - Insert into `otp_codes`: `expires_at = now + 5min`, `attempts = 0`, `used = false`.
   - `mailer.send({ to: email, subject: 'Your OTP', text: code })` → prints to console in dev.
5. Response (always identical):
```json
{ "message": "Nếu email hợp lệ, mã OTP đã được gửi. / If the email is valid, an OTP has been sent." }
```

### `POST /auth/verify-otp`
1. Validate email + 6-digit code.
2. Fetch latest `otp_codes` row for email: `used = false`, `expires_at > now`, ordered by `created_at DESC`.
3. If none → `401 INVALID_OTP`.
4. If `attempts >= 5` → `401 INVALID_OTP` (locked; user must re-request).
5. Compare `sha256(code+email)` to `code_hash`:
   - Mismatch → `attempts += 1`, return `401 INVALID_OTP`.
   - Match → set `used = true`, load user, issue JWT.
6. Response:
```json
{ "token": "eyJ...", "user": { "user_id": 5, "name": "...", "role": "employee" } }
```

### Hashing helper (`services/otp.js`)
```js
const crypto = require('crypto');
const hash = (code, email) =>
  crypto.createHash('sha256').update(`${code}:${email}`).digest('hex');
```

### JWT
- Payload: `{ user_id, email, role }`, `expiresIn: '12h'` (prototype).
- `auth.js`: read `Authorization: Bearer`, verify, attach `req.user`, else `401 UNAUTHORIZED`.
- `role.js`: `requireRole(...roles)` → `403 FORBIDDEN` if `req.user.role` not in list.

### Rate limiting
- `express-rate-limit` keyed by `req.body.email`, window 1h, max 5, on the request-otp route only.
- Return same generic message on limit (don't leak that the email is rate-limited).

### Error codes
`UNAUTHORIZED` 401 · `FORBIDDEN` 403 · `INVALID_OTP` 401 · `VALIDATION_ERROR` 422.

### Verify before closing the day
- Unknown email → 200 generic, **no console OTP printed**.
- Known email → OTP printed, verify → JWT.
- Wrong code 5× → locked; re-request works.
- Expired code (manually backdate `expires_at`) → 401.
- Reused code → 401.
- Call a protected route with/without token → 200 / 401, wrong role → 403.
