## 🔧 Implementation details

### `GET /vehicles/available?date=`
- Required `date` (YYYY-MM-DD).
- For each `active` vehicle, compute fixed slots **minus** slots already taken that date.
- "Taken" = booking exists for `(vehicle_id, date, slot_start)` with `status IN ('pending','approved')`.
- Return only vehicles with ≥1 open slot; include `available_slots[]`. Employees never see taken slots.

### `POST /bookings`  (employee, admin)
Body: `vehicle_id, booking_date, slot_start, slot_end, destination, purpose, passenger_count, contact_number`.
1. Validate fields; verify `slot_start/slot_end` is one of the 5 fixed slots → else `422 INVALID_SLOT`.
2. **App-level check:** `SELECT` existing booking for `vehicle_id + date + slot_start` with `status IN ('pending','approved')` → if found, `409 SLOT_CONFLICT`.
3. `INSERT` with `status = 'pending'`, `user_id = req.user.user_id`.
4. **DB safety net:** wrap INSERT; on MySQL error `1062` (duplicate key) → `409 SLOT_CONFLICT`.
5. Response 201:
```json
{ "booking_id": 101, "status": "pending", "message": "Booking submitted. Awaiting admin approval." }
```

### `GET /bookings`  (scoped)
- Employee: force `WHERE user_id = req.user.user_id` (server-enforced, ignore any client filter).
- Admin: all bookings + optional filters `date, vehicle_id, department, status, employee_name, page, limit`.
- JOIN users + vehicles for `employee_name, department, vehicle_name`.
- Response: `{ total, page, limit, data: [...] }`.

### `PATCH /bookings/:id/status`  — transition rules (enforce server-side)
| Actor | Allowed transition | Precondition |
|---|---|---|
| Employee | → `cancelled` | own booking AND status = `pending` |
| Admin | → `approved` / `rejected` | status = `pending` |
| Admin | → `cancelled` | status `pending` or `approved` |
| Admin | → `completed` | status = `approved` |
- `completed` / `cancelled` / `rejected` are terminal → no further transitions.
- Violations → `403 FORBIDDEN` (wrong actor) or `422 VALIDATION_ERROR` (illegal transition).

### Error codes
`SLOT_CONFLICT` 409 · `INVALID_SLOT` 422 · `NOT_FOUND` 404 · `VALIDATION_ERROR` 422 · `FORBIDDEN` 403.

### Verify before closing the day
- Book a slot → 201 pending; book same slot again → 409.
- Two near-simultaneous POSTs to the same slot → exactly one 201, one 409 (proves DB constraint).
- Employee sees only own bookings; admin sees all.
- Employee cancels own pending → ok; tries to approve → 403.
- Admin approves pending → ok; tries to approve a completed → 422.
