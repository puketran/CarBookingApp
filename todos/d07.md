## 🔧 Implementation details

### Backend — booking code
- Reads: add to `BOOKING_SELECT` →
  `CONCAT('BK-', DATE_FORMAT(b.created_at, '%Y'), '-', LPAD(b.booking_id, 4, '0')) AS code`.
- `POST /bookings` response: include `code` (compute `BK-${new Date().getFullYear()}-${String(insertId).padStart(4,'0')}`).
- No migration needed (derived from id + created_at).

### Wizard (`client/src/pages/BookVehicle.jsx` → wizard)
- AntD `Steps` with 4 items; local state `{ step, date, slot, vehicleId, details }`.
- **Step 1:** `DatePicker` (disable past) + `Select`/segmented for the 5 slots (`GET /slots`).
- **Step 2:** call `GET /vehicles/available?date=`; show `VehicleCard`s **filtered** to those whose `available_slots` include the chosen slot; first = `nearest`.
- **Step 3:** Quick-Book preset buttons prefill `destination`/`purpose`; fields: destination, purpose, passengers (max = vehicle capacity), contact. Name/department NOT asked (server uses the logged-in user).
- **Step 4:** summary card (date · slot · vehicle · destination · pax) + **Submit**. On 201 → success toast w/ code → `/my-bookings`. On 409 → toast, jump back to Step 2 and refresh availability.
- Keep the existing single-screen logic as the fallback only if needed; otherwise replace.

### Quick-Book presets (config)

```js
export const QUICK_BOOK = [

  { key: 'custom',  label: 'Custom',       destination: '',                 purpose: '' },

```

### My Bookings — tabs + detail
- AntD `Tabs`: All / Upcoming / Past / Cancelled. Filter the loaded list client-side:
  - Upcoming = `booking_date >= today` and status in (pending, approved)
  - Past = `booking_date < today` or status = completed
  - Cancelled = status in (cancelled, rejected)
- `BookingCard` uses `booking.code` (fallback to local compute). Tap → `Drawer` with all fields + `StatusBadge` + cancel (if pending).

### Profile (`client/src/pages/Profile.jsx`)
