## 🔧 Implementation details

### Migration 009
```sql
ALTER TABLE bookings ADD COLUMN driver_confirmed TINYINT(1) NULL; -- NULL=not acted, 1=confirmed, 0=declined
```
Add `b.driver_confirmed` to `BOOKING_SELECT`.

### Backend `routes/driver.js` (all `requireAuth` + `requireRole('driver')`)
- `GET /driver/trips` — `BOOKING_SELECT ... WHERE v.driver_user_id = req.user.user_id` (+ optional `?status=`), newest first.
- `PATCH /driver/trips/:id` body `{ action }`:
  - first verify the booking's vehicle has `driver_user_id = me` → else 404.
  - `confirm`: require status `approved` → set `driver_confirmed = 1`.
  - `decline`: require status `approved` → set `driver_confirmed = 0`, status → `pending`.
  - `complete`: require status `approved` → status → `completed`.
  - else 422.
- `PATCH /driver/vehicles/:id/status` body `{ status: 'active'|'maintenance' }` — require the vehicle's `driver_user_id = me`; update `vehicles.status`. (Maintenance vehicles already excluded from `/vehicles/available`.)
- Mount `router.use('/driver', driver)` in `routes/index.js`.

### Frontend
- `layouts/DriverLayout.jsx` — like EmployeeLayout but tabs: **My Trips** (`/driver`) · **Profile** (`/profile`). `App.jsx` `Shell`: `isDriver(role)` → DriverLayout.
- `pages/DriverTrips.jsx` — `GET /driver/trips`; reuse `BookingCard` (add small action row): Confirm/Decline when `status==='approved' && driver_confirmed==null`; Mark completed when `approved`. A header control to toggle the driver's vehicle maintenance (fetch the driver's vehicle via trips or a small `/driver/vehicles` — or derive from trips' vehicle_id).
- Drivers don't see Book / My Bookings tabs.

### Docs
- CLAUDE.md driver row: drop "(built in d09)" → built.
- `docs/roadmap-phase2.md`: renumber — **d08 driver** (was d09), **d09 = no-show/block rule (rules.md)**, shift M3+ accordingly.
