## 🔧 Implementation details

### Backend (`driverController` / `routes/driver.js`)
- `actOnTrip`: keep `confirm` (→ `driver_confirmed=1`). For **`complete`/`no_show`**: require `driver_confirmed === 1` AND `booking_date = CURDATE()` (compare in SQL or fetch the date); otherwise `422` with a clear message ("only on the trip day, after confirming").
- **`decline`**: accept `{ reason }` (validate optional string, trim). Keep status → `pending`, `driver_confirmed=0`. Notify:
  - employee (`notify(user_id, 'trip_declined', "Your trip #N was declined: <reason>", '/my-bookings')`),
  - admins (`notifyAdmins('trip_declined', "Driver declined booking #N: <reason>", '/admin')`).
  - (Reason is delivered via notifications; not persisted unless we add a column later.)
- Fetch `user_id` + `booking_date` in the trip lookup (BOOKING uses `b.user_id`; add `b.booking_date`).

### Backend profile (`authController` + `routes/auth.js`)
- `PATCH /auth/profile` (`requireAuth`) body `{ name?, department? }` → `UPDATE users SET ...` for `req.user.user_id`; return the updated public user. Validate strings (maxlen).

### Frontend `DriverTrips.jsx`
- Group: split trips into **Today** (`booking_date === todayYMD`) and **Upcoming/Other**; render Today section first with a header.
- **Detail drawer**: tap a trip card → Drawer with `Descriptions` (code, status, date·slot, employee_name, **contact_number (phone)**, department, destination, purpose, passengers). Stop row-click propagation on action buttons.
- Actions (bigger, `size="large"`, full-width-ish, right-aligned in a tidy column):
  - `approved && driver_confirmed == null` → **Confirm** / **Decline**.
  - **Decline** → Modal with a `TextArea` reason + **Send** → `PATCH /driver/trips/:id { action:'decline', reason }`.
  - `driver_confirmed === 1 && booking_date === today` → **Mark completed** / **No-show**.
  - Disable Complete/No-show with a hint when not today.
- Fix alignment: put `StatusBadge` + `confirmed` tag in a right-aligned flex column (consistent right edge).

### Frontend `Profile.jsx` + `AuthContext`
- Add an editable form (name, department) → `PATCH /auth/profile` → on success update context user (add an `updateUser(partial)` to AuthContext that merges + persists to localStorage). Keep the Change-password card.

### Verify before closing the day
- Confirm a trip; before the trip day Complete/No-show are disabled; on the day they work (and 422 if hit early via API).
- Decline with a reason → employee + admins get a notification containing the reason.
- Today group shows today's trips; detail drawer shows the phone number.
- Profile name/department edit persists and reflects in the header/JWT-independent UI. Client builds.
