# Day 20 — Admin booking ops & workflow (from request06)

> Eight admin-side asks raised after running the console (`todos/request06.md`).
> Includes two **business-rule changes** (slots auto-approve; full-day can span
> multiple days) plus UI/workflow polish on the bookings table, calendar,
> notifications, dashboard, and user creation.

**Decisions (confirmed with user):**
- **Slots auto-approve, still rejectable** — a slot booking is created `approved`
  (locks instantly). Admin can still reject an `approved` slot to free the vehicle
  for a full-day request (`approved → rejected` now allowed). Full-day stays
  `pending` → admin approval. Weekly limit & no-show block still apply to slots.
- **Multi-day full-day = date range → grouped rows** — pick start+end; one booking
  row per day, all sharing a `booking_group_id`; approve/reject/cancel acts on the
  whole group; if any day conflicts the whole request fails (transaction). Full-day
  is **exempt from the weekly limit** (multi-day inherently spans the week).
- **Dashboard popup counts pending full-day + new slots since last visit**; OK →
  bookings "Needs action" tab.

Admin can triage fast: slots flow through without approval but stay rejectable,
full-day reservations can cover a range of days, the bookings table is
customizable (columns/group/hide-old), notifications and calendar open an
actionable booking popup, and admins can create accounts with a password.

## 🔧 Implementation details

- **T1** `bookingController.create`: insert slot as `'approved'` (full-day stays
  `'pending'`); tailor notify + response message. `ADMIN_TRANSITIONS.approved` adds
  `'rejected'`. Route `body('status')` already allows `rejected`.
- **T2** Migration `019_add_booking_group.sql` (`booking_group_id INT NULL`, index).
  `create`: optional `end_date`; full-day iterates each day in `[booking_date,
  end_date]` inside a `pool.getConnection()` transaction — per-day advance/conflict/
  existing-full-day checks; insert N rows; set `booking_group_id` = first id on all.
  Full-day skips weekly-limit. `updateStatus`: if target row has a group_id, apply
  the same transition to every group row currently in the same status; notify owner
  once. Add `b.booking_group_id` + `group_days` (correlated COUNT) to `BOOKING_SELECT`.
- **T3** `BookVehicle.jsx`: full-day mode = 2-click range (`date` start, `endDate`).
  Highlight in-range days `selected`; "Continue" → step 3; summary shows the range;
  `submit` sends `end_date`. Server validates per-day.
- **T4** `dashboardController.inbox` + route `GET /dashboard/inbox?since=`:
  `{ full_day_pending, new_slots }` (new_slots = slot rows `created_at > since`).
  `AdminDashboard`: on mount read `localStorage.adminInboxSeen`, fetch, if any > 0
  show `Modal.confirm`-style popup; OK → `navigate('/admin')`; either way set seen=now.
- **T5** `AdminBookings`: master `ALL_COLUMNS` with stable `key`s; visibility+order
  state persisted in `localStorage.adminBookingsCols`; "Columns" popover with
  checkboxes + ▲▼ reorder; render filtered/ordered columns.
- **T6** `AdminBookings`: `Switch` "Group by day" → sort by date + rowSpan-merge the
  date column; `Switch` "Hide past & completed" → filter `booking_date >= today` and
  active statuses. Client-side over loaded `data`.
- **T7** New `client/src/components/BookingDetailModal.jsx` `{ bookingId, onClose,
  onChanged }`: fetches `GET /bookings/:id`, shows fields + StatusBadge + group note;
  admin action buttons by status (pending→approve/reject, approved→complete/reject);
  PATCH then `onChanged()`.
- **T8** `notify`/`notifyAdmins` booking links carry the id (`/admin?focus=<id>`).
  `NotificationBell.openItem`: if `type` starts `booking_` and id parseable → open

- **T9** `AdminCalendar` drawer: make each booking card clickable → `BookingDetailModal`;
